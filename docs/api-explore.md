# 怎么自己摸官方接口 —— 方法 + 工具

> 这份文档是给**你自己探路**用的。
> 我（AI）探到的结论都在 `docs/source-recon.md`，但**方法比结论重要** ——
> 因为你知道自己需要什么数据，而我不知道。

---

## 一、先说清官方接口长什么样

三角洲行动的网页数据（物品、价格、集市、制造、战绩……）**全走同一个地址**：

```
POST https://comm.ams.game.qq.com/ide/
Content-Type: application/x-www-form-urlencoded
Referer: https://df.qq.com/

表单体：
  iChartId      ← 哪一块数据（相当于"频道号"）
  iSubChartId   ← 一般等于 iChartId
  sIdeToken     ← 和 iChartId 配对的口令
  method        ← 想调哪个方法（有些频道要）
  action        ← 另一种区分方式（有些频道用这个）
  source        ← 常见 1 / 2 / 5，语义不明，照抄即可
  param         ← 通常是一段 JSON 字符串
```

**这就是为什么"自己试"很重要** —— 一个地址 + 一堆自由参数，
多试一个组合就可能多一张表出来。

响应统一是：

```json
{"ret":0,"iRet":0,"sMsg":"ok","jData":{"data":…}}
```

`ret != 0` 就是失败。**但它的报错文案经常和真实原因无关**（见第三节）。

### 登录 Cookie

需要登录的接口要带：

```
Cookie: openid=…; access_token=…; acctype=qc; appid=101491592
```

这四个字段来自 `npm run login`（扫码）之后存下的 `get-data/data/auth.json`。
`acctype` 是平台（`qc` = QQ，微信是另一个值），`appid=101491592` 是三角洲的。

## 二、我是怎么进的（三步，可复制）

### 第 1 步：找到"频道号 + 口令"

这两样**写死在官方前端 JS 里** —— 它们不是秘密，但也不是文档。
两条路：

| 路子 | 怎么做 |
|---|---|
| **看第三方项目** | 搜 GitHub 上的三角洲工具项目，它们的源码里通常直接抄了这些常量（我就是这么拿到 `352143:YWRywA` 的）|
| **看官方页面自己发请求** | 更靠谱，见下面第 3 步 |

### 第 2 步：从已知频道往外试参数

拿到一个 `iChartId:token` 只是拿到了**频道**。
同一个频道里，`method` / `action` / `source` / `param` 不同，返回的东西完全不同。

**我的第一个真结论就是错的**，因为没做这一步：

> 军需处 `530479` 我**只试了 `action=1`**，它返回
> 「抱歉，目前访问人数太多！请稍后再试！」——
> 我信了这句话，写下"集市没有官方接口"。
> 后来换成 `action=3`，集市整张表就出来了。

### 第 3 步：做**对照实验**

同一个请求，只改一个变量，对比结果：

| 对照 | 结论 |
|---|---|
| 带 Cookie vs 不带 | `ret=0` vs `ret=101 请先登录` → **这个要登录** |
| POST vs GET | 同样参数，POST 有数据、GET 报 `ret=101` → **它只认 POST** |
| `action=1` vs `2` vs `3` | 1 报"人多"、2 返回**空数组**、3 是**真数据** |
| 参数放 body vs 放 URL | body 有数据、URL 上返回结构完全不同的东西 → **必须放 body** |

**这三步就是全部**。没有魔法，就是"改一个变量、看结果"。

## 三、⚠️ 三个"报错在骗人"的案例（能省你几小时）

| 看到 | 别信它 | 真实原因 |
|---|---|---|
| `ret=-4000`「抱歉，目前访问人数太多！」 | 跟人多没关系 | **参数组合不对** |
| `ret=101`「非常抱歉，请先登录！」 | 不一定缺登录 | **也可能是把 POST 写成了 GET** |
| `ret=0` 但 `jData.data` 是 `[]` | 不是"没数据" | **参数组合不对**（`action=2` 就是这样）|

还有两种"看起来没数据"其实是**解析问题**（不是接口问题）：

- 值是 **URL 编码**的 —— `"11050004004%2C1"` 里的 `%2C` 是逗号。
  不解码就会把整串当成一个 ID → 校验不过 → **每条都被静默跳过**。
- **嵌套层数不一样** —— 有的接口是 `jData.data.data`，
  军需处是 `jData.data` 直接挂数组。认死一种就会"拿到数据却报结构错了"。

> **一句话**：别信文案，去看**原始响应**。
> 所以 `npm run ide` 默认会把原始响应打出来 ✓

## 四、工具：`npm run ide`

### 最常用

```bash
# 看已知的频道表
npm run ide -- --list

# 打一个请求（频道号:口令 + 参数）
npm run ide -- 530479:SwgEeH action=3

# 只给频道号也行（口令从已知表里查）
npm run ide -- 530479 action=3

# 对照实验：不带登录
npm run ide -- --no-auth 530479:SwgEeH action=3

# 对照实验：用 GET 而不是 POST
npm run ide -- --get 530479:SwgEeH action=3

# 响应太大：存文件 / 全打印
npm run ide -- --out=x.json 530479:SwgEeH action=3
npm run ide -- --full 530479:SwgEeH action=3
```

每次都会打印：
`HTTP 状态` · `ret/iRet/sMsg` · **第二层的 code/msg**（很多接口的真报错在这层）
· `jData` 的键 · **数据形状（数组几条 / 对象有哪些键）** · 原始响应（截断 1500 字节）

**最后还会打印一段 `fetch(...)`** —— 直接粘到浏览器 F12 的 Console 里就能复现同一个请求 ✓

## 五、怎么发现**新**频道（最有用的部分）

官方的活动页 / 助手页 / 小程序在后台打的请求，就是你要的东西。
抓法：

1. 打开官方页面（`df.qq.com` 上的活动页、或游戏内嵌的网页），**F12 → Network**
2. 过滤栏输 `ide` 或 `ams`
3. 在页面上点你要的功能（点开"集市"、"制造"、"战绩"……）
4. 看新冒出来的请求 → 点 **Payload / 请求体** → 里面就是
   `iChartId` + `sIdeToken` + 其余参数
5. 右键 → **Copy as cURL** → 用 `npm run ide` 里的那段 `fetch(...)`（或直接改命令行）复现
6. 拿到之后**改参数试**（第 2、3 步的套路）

> 小程序的包里也有这些请求，但网页版最容易看。

## 七、礼貌与安全（务必）

1. **慢慢来**：一次一个请求，间隔 1 秒以上。这个接口是官方生产接口，
   高频打会被限流（甚至封号风险）。
2. `npm run ide` 用的是我们自己的 `HttpClient`（串行 + 限速 + 重试 + 403/429 立刻停）。
3. **别把 `auth.json` 给任何人**，也别提交到 git（它已被 `.gitignore` 覆盖）。
4. 只用**你自己的账号**、只探**你自己能看到的数据**。
5. 探到的东西**不用写进代码也能先记在 `docs/source-recon.md`** —— 那是我们的结论库。
