# 人工标注目录

这个目录放**你手工维护的数据**，会入库 git（是你的知识资产，值得有版本历史）。

---

## 三个文件，各管一件事

| 文件 | 管什么 | 初始状态 |
|---|---|---|
| `provenance.json` | **出产地** —— 这个物资能在哪些地图拾到 | 空 `{}` |
| `item-attributes.json` | **可获得性 / 可上架 / 每组发数** 三个属性 | 空 `{}` |
| `provenance-todo.csv` | 在上面两个文件里填数据的**工作区**（可重新生成，不入库） | 自动生成 |

外加两个 `*.example.json` 格式示例，可以删。

---

## 为什么需要它们（每一个都对应一个实测过的坑）

### ① 出产地 `provenance.json`

官方接口有个第三方站完全没有的字段 `propsSource`，但**实测覆盖得很差**：

```
收集品    323 / 586 = 55.1%      ← 缺 263 条
钥匙        0 /  80 =  0.0%      ← 一条都没有
其它子类    0 /  ...             ← 完全没有
```

而**钥匙恰好是单格价值最高的那批**。不需要一次补完 —— 从高价值往下补，补到够用就行。

### ② 可获得性（`item-attributes.json` 的 `availability`）

官方数据只告诉你"这个物品存在、价格多少"，**不告诉你它能不能拾到**。

⭐ **关键是分清两种“现在拾不到”** —— 它们对掳金决策的意义完全不同：

| 值 | 标签 | 含义 | 会不会变 |
|---|---|---|---|
| （默认，不用写） | **可摸** | 局内可以拾到 | —— |
| `expired` | **限时下架** | 曾经能拾，现在不行了（赛季结束 / 活动结束）| ⚠️ **可能返场** |
| `unobtainable` | **非战利品** | 机制上不作为战利品产出（只能兑换 / 制造 / 任务奖励）| 不随赛季变化 |

**例子**：
- 旧赛季子弹 → 「**限时下架**」（赛季返场时就又能拾了）
- 只能军需处兑换的道具 → 「**非战利品**」（永远不是地上能拾的东西）

> 旧叫法「已失效」「不可摸」仍然能认，但**不推荐再用** ——
> 它们只说了“现在拾不到”，没表达“会不会回来”，而这正是最需要的信息。

### ③ 可上架（`item-attributes.json` 的 `listable`）

**交易行上能看到价格，不等于你能拿到那个价格。**

典型例子：**旧赛季子弹** —— 有交易行价格，但无法上架，只能卖军需处。

| 值 | 含义 |
|---|---|
| **可上架**（默认，不用写） | 能挂到交易行卖，交易行价就是你能拿到的钱 |
| `false` / 写「否」 | **不能上架**。判定变成「未知」，**不按交易行价算** |

> ⚠️ 这里指的是"**物品本身**能不能上架"（类型级）。
> 另一种"从交易行买来后被标记为绑定"是**实例级**的，对摸金没影响
> （从地上摸到的东西从来不是绑定的），所以不在这个字段里。

### ④ 每组发数（`item-attributes.json` 的 `unitsPerSlot`）

**这是最重要的一个，因为不知道它，子弹的价值会算错 60 倍。**

实测：交易行报的是**每发单价**，而一个格子能放 **60 发**（部分 90 发）。

```
5.56x45mm M855A1   现价 1,666/发   1×1
  不填 → 单格价值算不出来（显示"待补"）
  填 60 → 单格价值 = 1,666 × 60 = 99,960/格
```

⚠️ **因弹而异，同一口径都可能不同**（实测 `6.8x51mm Hybrid` 是 60、`6.8*51mm PLY-III` 是 90），
所以要一个一个填，不能按口径批量。

**其余所有物品默认是 1**（一个格子放一个），不用管这一列。

### ⑤ 赛季限定（`item-attributes.json` 的 `seasonal`）

⭐ **这个是为了让你不用每赛季手工改状态。**

### 它适用于**任何物品**，不只是子弹

赛季更替会让一批东西同时变状态，**子弹只是其中最典型的一种**：

| 什么会随赛季变 | 本季 | 往季后 |
|---|---|---|
| **赛季弹药** | 可摸 + 可上架 | 限时下架 + 不可上架（只能卖军需处）|
| **赛季战利品**（活动限定收集品等）| 可摸 | 限时下架 |

如果直接写死 `availability` / `listable`，你**每赛季都要手工把几十条改一遍**（而且很容易漏）。
所以只记「本季 / 往季」，让程序**自动推导**：

| 标了什么 | 自动推导出的状态 |
|---|---|
| `seasonal: "current"`（本季）| 可摸 + **可上架** |
| `seasonal: "past"`（往季）| 限时下架 + **不可上架** |
| 没标 | 由 `availability` / `listable` 或默认值决定 |

### ⚠️ 注意“可上架”那一条是**假设**，遇到例外要显式覆盖

上面的推导把两件事一起改了：

```
往季  →  摸不到  AND  卖不掉
```

这是实测于**赛季弹药**的规则。但非弹药的东西不一定如此 ——
比如某个赛季收藏品，往季后**摸不到了，却可能仍能挂交易行卖**。

这种例外用**显式写法**覆盖（优先级：**显式 > 赛季推导 > 默认值**）：

```json
"某赛季收藏品": { "seasonal": "past", "listable": true }
```

### ⭐ 换季时你要做的两件事

```bash
# 1. 把上赛季那批标成「往季」（先跑这个！）
npm run season:rollover              # 预览，不写文件
npm run season:rollover -- --apply   # 确认后真的改

# 2. 把本赛季的新东西标成「本季」
#    在 CSV 的「赛季限定」列写「本季」，或 JSON 里写 "seasonal": "current"
```

⚠️ **顺序不能反**：先跑 rollover，再标新的。反了的话新的会被一起改成往季。

> 💡 不换季的时候什么都不用管。程序每次拓取会检查一致性，发现
> “标了本季却写着不可上架”这种矛盾会提醒你。

## 格式

### `provenance.json` —— 出产地

```json
{
  "鱼月徽权杖首":     ["长弓溪谷", "航天基地"],
  "15050600003":     ["巴克什"],
  "海洋之泪":         { "mode": "append", "sources": ["零号大坝"] },
  "某条错误数据":      []
}
```

- **键**：物品名 或 官方 ID。两者都写时 **ID 优先**（不怕官方改名，可作"钉子"）
- **值**：
  - `["长弓溪谷"]` —— 简写，等价于 `mode: "replace"`（**90% 的情况写这个**）
  - `{ "mode": "append", "sources": [...] }` —— 官方值不全、想**追加**时用
- **空数组 `[]`** —— 显式删除出产地
- **特殊值 `全地图`** —— 所有地图都会出，在任意地图筛选下都算"已确认"

#### ⚠️ 字段含义："能在这张图拾到"，不是"它属于这张图"

| 物品 | 应该填什么 | 为什么 |
|---|---|---|
| 普通收集品、改装件 | 你能确认的那些图 | —— |
| **普通钥匙**（如「雷达站无人机平台」）| `全地图` | 钥匙从**任何图的容器里**都能拾到 |
| **Boss 专属掉落**（如「酒店国王房」）| **那一张图** | 别的地图不刷对应 Boss，所以不会掉落 |
| 全图都能刷的收集品 | `全地图` | —— |

所以「酒店国王房 → 长弓溪谷」和「雷达站无人机平台 → 全地图」**不矛盾**。

#### 关于点位

**只写地图名，不要写点位。** 就算你写了 `"长弓溪谷-水泥厂"`，程序也会自动截断成 `"长弓溪谷"`。

原因：官方点位数据不可靠（很多全图都刷的物资只标了某几个"核心区"），**显示一个不可靠的精确信息比不显示更糟**。

### `item-attributes.json` —— 三个属性

```json
{
  "某活动限定物品": "限时下架",
  "某只能兑换的物品": { "availability": "unobtainable", "note": "只能军需处兑换" },
  "5.56x45mm M855A1 APC+": { "seasonal": "past", "unitsPerSlot": 60, "note": "旧赛季弹药" },
  "6.8x51mm Hybrid": { "seasonal": "current", "unitsPerSlot": 60 },
  "6.8*51mm PLY-III": { "seasonal": "current", "unitsPerSlot": 90 },
  "15050600003": { "availability": "unobtainable" }
}
```

- **简写**：直接给状态字符串 = 只标可获得性
- **完整**：`{ availability, listable, unitsPerSlot, seasonal, note }` —— 五个字段都可选，**只写你知道的**
- `note` 是标注理由，可选，但写下来以后自己看得懂
- ⭐ **优先级：显式写的 > 赛季限定推导 > 默认值**
  （处理例外：比如某颗往季弹返场了，可以标 `seasonal: "past"` 但显式写 `listable: true`）

## 推荐的录入流程

### 1. 导出清单

```bash
npm run provenance:todo --emit csv
```

生成 `provenance-todo.csv`，**分两段**：

- **第一段 ⚠️ 待补**：有价格但算不出单格价值的（主要是没填每组发数的弹药），**按子类分组**
  —— 这样同一口径的子弹排在一起，Excel 里可以拖动填充
- **第二段**：已能排序的，按单格价值降序

⭐ **重新运行这个命令不会丢你已填的内容** —— 它会先读一遍旧 CSV，把用户要填的那几列按官方ID 搬过来，并且会从已导入的标注文件回填。

### 2. 在 Excel 里填这五列

| 列 | 怎么填 |
|---|---|
| **你填的地图** | 这个物品**能在这张图拾到**才写。多个用 `、` `,` `/` `\|` 或空格分隔。写 `-` 表示确认没有出产地 |
| **可获得性** | 留空 = 可摸；或写 `限时下架`（可能返场）/ `非战利品`（机制上不产出） |
| **每组发数** | **只对弹药有意义**：一个格子能放多少发（60 或 90）。非弹药留空 |
| **可上架** | 留空 = 可上架；**不可上架**的写 `否` |
| **备注** | 可选。标注理由 |

「模式」列已经预填好了（官方没数据 → `替换`；官方有数据 → `追加`），一般不用动。

### 3. 回写

```bash
npm run provenance:import
```

⚠️ **「留空」的含义是「不动」，不是「清空」**，而且是**逐字段**判断的：

- 你这次只填了「每组发数」→ 这条的「可获得性」「可上架」保持原样
- 想恢复默认值要**显式写**（可获得性写「可摸」、可上架写「是」）

这是刻意的安全设计 —— 否则 CSV 里 1500+ 行留空再导入，会把你已有的标注全删掉。

#### 关于「同名物品」（你普通不用管）

官方实测有 **6 组同名物品（13 条）**，最坑的是 `.300BLK`：
**3 条不同品质、价格差 11 倍的子弹共用一个名字**。

如果用名字做标注键，给其中一条的标注会**同时打到三条**。所以导入时：

- **名字唯一** → 用名字做键（`"海洋之泪": {...}`，好认）
- **名字有歧义** → 用官方ID 做键（`"37280300001": {...}`，精确）

脚本会自动判断，并打印出来：

```
[1/4] 读取 CSV：1576 行数据
      检测到 6 个同名物品（共 13 条）→ 这些改用官方ID作键：
        · .300BLK（3 条）
        · 巴克什藏宝图8号（2 条）
        ...
```

**你要做的事：没有。** 在 CSV 里直接按行填就行（每行都带官方ID）。
只有一件事要知道：**旧版遗留的同名名字键会被自动迁移**，
你会看到一行 `↻ 迁移了 6 个同名旧键 → 官方ID 键`。

> 想回到旧行为：`npm run provenance:import -- --key name`（全用名字）
> 或 `--key id`（全用官方ID）。加载器两种键都读（先 ID 再名字）。

### 4. 看效果

```bash
npm run fetch
```

## 写错了会怎样

程序**尽量容错，绝不因为格式错误而崩溃**：

| 情况 | 行为 |
|---|---|
| JSON 语法错误（少个逗号） | 明确报错 + **跳过那个文件的全部标注**，官方数据照常使用，服务不挂 |
| 某个键的值类型不对 | 报错指出**是哪个键**，只跳过这一条 |
| 键匹配不到任何物品 | 警告日志，一次性列出所有没匹配上的键 |
| **地图名打错了** | ⚠️ **软校验警告**：这个地图名在官方数据里从未出现过，并列出官方见过哪些（**只警告不阻拦**，因为将来可能出新地图） |
| 「每组发数」填了非正数 | 当作没填 → 该条单格价值显示"待补" |
| 「可上架」填了认不出的词 | 当作没填（沿用默认"可上架"），不会猜 |
